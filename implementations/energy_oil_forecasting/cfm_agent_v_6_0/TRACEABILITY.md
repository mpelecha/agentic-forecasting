# CFM Agent v6.0 traceability

Every normative requirement of `SPECIFICATION.pdf` (final, 2026-09-16) mapped to the code that
implements it and the test that proves it. Status values: `implemented` (code and test present and
green in the package suite), `pending (step 9)` and `pending (step 10)` for the validation and
packaging gates that are recorded in `BUILD_VERIFICATION.md` and `LIVE_VALIDATION.md` when run.

## Deviations from the original planning documents

Recorded in Section 12 of the specification and mirrored in `DECISIONS.md`:

| Topic | Original planning documents | v6.0 | Decision |
|---|---|---|---|
| Quantile levels | Five | Eleven (the five are a subset) | DD-05 |
| Price floors | $0.01 | $1.00 input, simulated, and final; April 2020 kept; sensitivity report | DD-06 |
| Uncertainty ladder | Dollar targets from absolute-deviation percentiles | Coverage-shaped ratio anchored at the 80% band | DD-10 |
| Directional guard | Not defined | Wrong-sign percentile gives exactly zero with a warning | DD-09 |
| Novelty gate | Only two classes may act | All four act with multipliers; no tier cap | DD-11 |
| Tier 3 | Three publishers, primary source, physical claim, likely-new novelty | Two publishers and 0.80 confidence | DD-12 |
| Release path | Staged v5.8, v5.9, v6.0 | Direct v5.2 to v6.0 | DD-02 |

## Implementation readings that are not deviations

| Topic | Reading taken |
|---|---|
| Anchor coverage | The settings validator requires `uncertainty_anchor_coverage` to equal the `unchanged` rung. Section 3.3 requires the unchanged action to yield exactly 1.0, which only holds when both look up the same band. |
| Carried research fields | `research_max_passages_per_source` and `research_passage_chars` are the two v5.2 research fields still read by the audit-only source validator; Section 7.3 carries every other v5.2 research field over verbatim, so they sit under `[research]`. |
| Component seed | The component generator is `numpy.random.default_rng(seed_i)` where `seed_i` is the 32-bit state drawn from the i-th child of `SeedSequence(suite_seed).spawn(3)`; the same integer is LightGBM's `random_state`, so the recorded seed reproduces the component alone. |
| Passage summary index | `SS` is the summary's 1-based position in `packet.verified_summaries` (all four categories), so a failed-closed category still consumes its index and ids stay stable across runs. |
| Bullet markers | `-`, `*`, `N.`, and `N)` count as bullets only when followed by whitespace or the end of the line, so `-5%` is not stripped. |
| Abbreviation token | The whitespace-delimited token ending at the terminator run is matched raw and case-sensitively against `passage_abbreviations`. |
| Publisher union | Rejected claims are excluded from the publisher count but do not by themselves fail the action; the union runs over the valid cited claims (Section 4.2). |
| Input-floor activations | Counted on the windowed prices the models consume; identical to the full-history count when the window is 0. |
| LightGBM rows | Eligibility is checked on the aligned frame's `rows_remaining` after fill and drop, the audited figure; the fitted rows are those with every lag observed. |
| Future level covariates | `oil_curve_contango_l1b` and `vix_level_l1b` are held at their latest served value in the window; every other covariate is a return set to 0 (identifier rule: "contango" or "vix" in the id names a level). |
| Sensitivity mechanics | `release.py sensitivity` removes the target observations on `sensitivity_excluded_dates`; the two returns into and out of each removed observation are replaced by one bridging return. |
| Effective parameters | The main role's parameters are recorded when the `LiteLlm` object is built and again at the start of every workflow after the recorder is reset, so the audit carries them per run. |
| E2B preamble | `import json as _cfm_json`, three `NAME = _cfm_json.loads(...)` assignments, then `del _cfm_json`, leaving exactly `DIAGNOSTICS`, `MODEL_SUITE_QUANTILES`, `TASK_BINDING` in the sandbox namespace before the script. |
| Preflight timeout | Section 10.2 names no timeout; the listing request and the probe use `cutoff_verifier_timeout_seconds`. |
